# 工具系统

工具是 Anybox 允许 Agent 读取项目、检索上下文、执行命令和推进工作流的能力边界。工具页面既是一个全局可用性开关，也是理解每项能力、风险和输入格式的目录。

> 本页描述当前桌面端与 Agent 运行时的实际设计。可见工具会随操作系统、工作区类型、已连接的 MCP 服务和当前 Agent 策略变化。

## 页面如何组织

从桌面端左侧导航打开「工具」。页面由分类导航和工具详情两部分组成：

1. 分类导航只显示当前有工具的类别，并同时显示该类别的工具总数与启用数。
2. 详情区先显示当前类别与全局启用状态，再列出该类别中的工具。
3. 每一行保留标题、稳定 ID、能力标签、风险标签和启停开关；展开后才显示完整描述、别名、并发策略和输入 Schema。

这种布局让日常启停保持紧凑，同时把面向调试和集成的技术信息放进按需展开的层级。

### 分类与含义

工具按以下顺序分组；没有工具的类别不会占据导航空间。

| 类别 | 主要用途 | 常见能力边界 |
| --- | --- | --- |
| Shell | 操作系统命令、终端进程和远程 Shell | 通常需要 Shell 权限 |
| Write | 修改文件或工作区内容 | 可能产生不可逆变更 |
| Delegation | 创建、读取、等待或停止子 Agent | 可能把工作交给其他运行单元 |
| Workflow | 控制任务、回滚、依赖加载或工具编排 | 会影响任务执行路径 |
| Interaction | 向用户提问或请求确认 | 会暂停当前流程等待输入 |
| Search | 按名称、路径、内容或定义检索上下文 | 默认只读 |
| Read | 读取文件、目录、图片、资源或运行状态 | 默认只读 |
| Other | 尚未归入上述类别的内置能力 | 以具体工具元数据为准 |

分类描述用途，不直接等同于授权结果。例如 `JavaScript Exec` 被归入 Workflow，因为它负责编排只读工具，并不提供主机 Shell。

### 工具行与展开详情

工具行中的信息来自运行时注册表，而不是前端维护的静态清单：

- 标题用于快速识别能力，工具 ID 是模型和运行时使用的稳定名称。
- 能力标签显示分类；风险标签根据 `readOnly`、`destructive`、`needsShell` 等元数据生成。
- 别名数量用于提示兼容名称；服务端保存时会把已知别名规范化为正式工具 ID。
- `Concurrency: safe` 表示该工具允许与其他安全工具并行调度，不表示它可以绕过权限检查。
- Input schema 是调用参数的完整结构，主要用于排障、开发自定义 Agent 和核对模型调用。

### 修改、保存与重置

切换某个工具时，页面会先更新本地草稿和启用计数。只有点击「保存更改」后，选择才写入全局配置。

「恢复默认」会立即清空显式覆盖项。空配置表示使用注册表默认值，因此当前设计下内置工具默认启用。恢复默认不会删除工具，也不会改变 MCP 服务配置。

页面还为以下状态提供独立反馈：

- 正在读取注册表与已保存配置。
- Agent 服务不可用或保存失败。
- 当前平台和工作区没有返回任何内置工具。
- 保存或重置进行中，相关按钮会暂时禁用。

## 可用性与权限不是同一件事

全局开关只决定一项内置工具是否可以进入后续的工具计划。一次调用最终能否执行，还要依次经过更多限制。

| 层级 | 负责什么 | 结果 |
| --- | --- | --- |
| 全局工具选择 | 用户是否在工具页面禁用了某项内置工具 | 禁用后不向当前 Agent 提供 |
| Agent 工具策略 | Agent 自身的允许列表、拒绝列表或只读策略 | 可进一步缩小工具集合 |
| 会话策略 | `session.policy.toolPolicy` 是否将当前会话设为只读 | 非只读工具会被排除 |
| 调用级权限 | 根据工具类型、路径、命令和风险评估本次参数 | 允许、拒绝或向用户询问 |
| 工具自身守卫 | 参数 Schema、路径边界、运行前验证和授权 | 验证失败时不会执行 |

因此，“已启用”不等于“无需确认”，关闭全局开关也不是修改系统权限。工具在真正执行前仍会经过同一套权限评估、审批和运行时校验。

全局选择以工具 ID 为键持久化。显式的 `false` 会禁用工具；没有记录则沿用默认值。服务端只接受当前注册表中存在的内置工具 ID 或别名，避免过期名称和任意配置进入运行时。

## 从注册表到桌面页面

工具模块共用一份运行时定义，界面、模型工具清单和执行器不会各自维护一套名称或 Schema。

```text
Tool.define
  ├─ ID / aliases / capabilities
  └─ title / description / parameters / execute
            │
            ▼
内置工具注册表 + MCP 工具 + 运行时自定义工具
            │
            ├─ GET /api/tools/builtins ──> Electron IPC ──> 工具页面
            │
            └─ resolveToolPlan ──> 权限评估 ──> execute ──> 规范化结果

工具页面 ── PUT /api/tools/builtins/selection ──> 全局配置
```

`Tool.define` 在初始化工具时统一包装参数校验、运行前守卫和结果规范化。执行层还会负责权限决策、取消信号、超大结果持久化以及面向模型的输出转换。

桌面页面通过只读接口取得内置工具摘要，通过单独的更新接口保存选择。更新接口会校验工具名称并只保存规范化结果，前端不直接写配置文件。

### 平台与工作区差异

内置注册表会根据环境组合工具：

- Windows 可以提供 PowerShell、CMD、Git Bash 和 WSL Bash；macOS 使用对应的系统 Shell。
- SSH 工作区使用 SSH Shell，并避免把只适用于本机工作区的终端和语言服务工具混入当前能力集。
- 工具数量和分类计数因此可能在不同设备或项目之间不同，这属于预期行为。

## 内置工具、MCP 与渐进式发现

运行时注册表最终会合并三类来源：

- 内置工具：随 Anybox 提供，并由本页的全局开关管理。
- MCP 工具：来自项目连接、插件或当前任务临时连接的 MCP 服务。
- 运行时自定义工具：由宿主在当前进程中注册的扩展能力。

工具页面目前只管理内置工具。MCP 的连接、认证、诊断和逐工具策略仍在「连接」模块中维护。

### 为什么需要渐进式工具搜索

当 MCP 服务很多时，把所有完整工具定义同时放入模型上下文会显著增加输入体积。Anybox 使用渐进式发现来控制这部分成本：

1. 内置工具、项目中持久配置的 MCP 服务和当前任务显式选择的 MCP 服务直接可见。
2. 其他符合条件的 MCP 工具先作为 deferred 工具保留在运行时注册表中。
3. 模型调用 `anybox_tool_search`，按能力、来源、名称或 Schema 字段搜索候选工具。
4. 匹配工具的完整定义在当前用户轮次中被激活，并从下一次模型调用开始可见。

搜索只针对 deferred MCP 工具，不会重复索引直接可见的工具。索引会综合工具 ID、模型名称、标题、描述、MCP 来源和输入 Schema，并支持英文词元与中日韩文本匹配。

如果内部工具开关 `tool_search` 被禁用、被当前 Agent 拒绝或当前没有 deferred 候选，运行时会回退到直接暴露可用工具，避免出现工具存在却无法发现的死路。`anybox_tool_search` 是它为避免供应商保留名称冲突而使用的模型侧别名。

## JavaScript Exec 编排

`exec` 让模型在一次工具调用中用 JavaScript 组织多个只读检索动作。它适合并行读取、条件筛选、聚合结果和减少模型与工具之间的往返次数。

当前实现刻意保持窄能力：

- 代码在新的、受资源限制的 QuickJS 运行时中执行。
- 只暴露 `tools.read_file`、`tools.list_directory`、`tools.glob` 和 `tools.grep`。
- 代码是异步函数体，支持顶层 `await`、循环、条件、`try/catch` 和 `Promise.all`。
- `return` 值必须可以序列化为 JSON；没有返回值时结果为 `null`。
- 不提供 Node.js、Bun、DOM、模块导入、网络、主机文件 API、`process`、`console` 或定时器。
- 不允许悬空工具调用；每个 Promise 都必须被等待、返回或显式处理失败。

例如，一次调用可以同时统计 TypeScript 文件和 TODO：

```json
{
  "code": "const [files, todos] = await Promise.all([\n  tools.glob({ pattern: \"src/**/*.ts\", maxResults: 200 }),\n  tools.grep({ pattern: \"TODO\", path: \"src\", literal: true, maxResults: 100 })\n]);\nreturn {\n  typescriptFiles: files.matches.length,\n  todoLines: todos.hits.length,\n  truncated: files.truncated || todos.truncated\n};"
}
```

返回结果包含最终 JSON、每个子工具调用的状态与耗时，以及整次执行耗时。子调用仍会重新检查全局选择、Agent 策略、会话限制和调用权限；任何需要用户审批的子调用都会在 `exec` 内拒绝执行。

### 资源与安全边界

| 限制 | 当前值 |
| --- | ---: |
| JavaScript 源码 | 32,000 字符 |
| 墙钟时间 | 30 秒 |
| 单次 CPU 执行片段 | 250 毫秒 |
| 运行时内存 | 32 MiB |
| 栈内存 | 512 KiB |
| 子工具调用 | 最多 64 次 |
| 单次参数 / 单次结果 | 各 50,000 字符 |
| 累计子工具结果 | 500,000 字符 |
| 最终输出 | 50,000 字符 |

这些限制用于控制失控循环、内存占用和上下文膨胀。QuickJS 只负责计算和 Promise 调度，真正的项目读取仍回到 Anybox 工具执行层；`exec` 本身不会获得被编排工具之外的主机能力。

## 使用建议与排障

- 只想临时阻止某项能力时，关闭开关并保存；需要恢复注册表默认状态时使用「恢复默认」。
- 工具已启用但模型仍看不到时，检查 Agent 工具策略、只读会话限制和当前平台是否注册了该工具。
- MCP 工具没有立即出现时，检查对应连接是否为项目持久连接、当前任务连接，或能否通过 `anybox_tool_search` 搜索到。
- `exec` 报告子工具不可用时，检查该子工具是否被全局或 Agent 策略禁用；写入、Shell 和 MCP 工具目前不能放进 `exec`。
- `exec` 报告未消费的调用时，确保所有 `tools.*` Promise 都被 `await`、`return` 或纳入已等待的 `Promise.all`。
- 输入 Schema 是排查参数名和类型的最终依据；工具标题和说明用于阅读，不应替代稳定 ID。
