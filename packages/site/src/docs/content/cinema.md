# anybox for cinema

anybox for cinema 用本地文件夹组织 AI 影视项目。它把创作过程限制在 `Text`、`Image`、`Video` 和 `Audio` 四类节点中，让 Agent 可以初始化项目、整理分镜、维护画布，并把实际素材和项目记录留在你选择的工作区。

> 项目文件夹是唯一事实来源，Anybox 是控制器，画布只是这些文件的可视化界面。插件不会保存模型供应商密钥，也不会自行充当视频生成服务；真正的生成任务由 Anybox Agent 的 Cinema Runtime 调用你已配置的供应商能力。

## 什么时候使用 Cinema

Cinema 适合这些工作：

- 从故事梗概、脚本或创意简报建立一个可继续编辑的影视项目。
- 把镜头说明、参考图、候选视频和音频素材组织成有连接关系的画布。
- 生成初版分镜，随后在同一项目中持续调整镜头、提示词与素材。
- 读取现有项目的节点、素材和事件记录，快速恢复上下文。
- 在本地保留创作资产，再由你选择的生成能力完成图片、视频或音频任务。

如果目标只是剪辑一个现成视频、播放媒体文件或操作某个桌面剪辑软件，应使用该软件自身能力或 Windows 电脑控制。Cinema 的重点是项目结构和 Agent 工作流，不是替代完整的非线性编辑器。

## 安装并为项目启用

1. 从 Anybox 左侧导航打开「插件」。
2. 搜索 `cinema` 或 `anybox for cinema`，阅读本地文件与画布写入权限后点击「安装」。
3. 在当前项目顶部菜单的插件选择器中启用 Cinema。
4. 打开或创建一个专门用于影片项目的本地工作区。
5. 新建任务并要求 Agent“初始化 Cinema 项目”，同时说明片名、类型、时长和当前已有素材。

初始化是可重复执行的：缺少的目录和基础文件会被补齐，已有用户文件不会被覆盖。如果关键 JSON 已损坏，Agent 会报告具体文件并停下来让你处理，而不会直接用空内容替换。

## 推荐的第一次任务

可以从一条边界清晰的请求开始：

> 在当前工作区初始化 Cinema 项目。项目是一支 45 秒的城市夜景短片，先创建三镜头分镜，只使用 Text 和 Image 节点；不要开始图片或视频生成。完成后列出新建文件和下一步需要我确认的内容。

随后按阶段推进：

1. 把创意简报、脚本和参考资料放入 `prompts/`、`references/` 或 `assets/`。
2. 先用 Text 节点确定故事、镜头和提示词，再创建 Image 节点承载构图参考。
3. 检查分镜顺序、节点连接和素材路径。
4. 需要生成时，在 Anybox 中配置相应供应商；密钥只保存在 Anybox，不写入项目。
5. 让 Agent 逐项生成或更新素材，并在每轮之后检查画布和事件记录。
6. 把最终输出放入 `renders/` 或 `exports/`，保留可追溯的项目结构。

## 项目目录

初始化后的项目通常包含以下结构：

| 路径 | 用途 |
| --- | --- |
| `.anybox-cinema/project.json` | 项目元数据与 Cinema 项目标识 |
| `.anybox-cinema/providers.json` | 供应商绑定信息；不应包含密钥 |
| `.anybox-cinema/canvas.json` | 节点、连接关系和画布状态 |
| `.anybox-cinema/tasks/` | Cinema 任务记录 |
| `.anybox-cinema/events.jsonl` | 可追加的项目事件记录 |
| `prompts/`、`references/` | 提示词、脚本和参考资料 |
| `assets/`、`generated/` | 用户素材与生成中的素材 |
| `renders/`、`exports/` | 渲染结果和交付文件 |
| `scripts/` | 项目自己的辅助脚本 |

`.anybox-cinema` 是项目控制数据，不要把供应商令牌、账号密码或其他秘密写进去。移动素材后，应让 Agent重新检查画布引用，避免节点仍指向旧路径。

## 四类节点

Cinema 只接受以下节点类型：

| 节点 | 适合表达 |
| --- | --- |
| `Text` | 故事、镜头说明、对白、提示词和制作备注 |
| `Image` | 概念图、分镜帧、角色或场景参考 |
| `Video` | 镜头片段、动画候选和渲染结果 |
| `Audio` | 配音、音乐、环境声和音效 |

这四类节点可以相互连接来表达依赖和创作顺序。插件会拒绝未知节点类型，而不是把无法识别的数据悄悄写入画布。

## 本地 MCP 工具

Cinema 带有一个本地 MCP Server，提供三项面向项目的能力：

| 工具 | 作用 | 默认审批 |
| --- | --- | --- |
| `cinema_get_project_summary` | 读取项目概要、节点与当前状态 | 自动 |
| `cinema_apply_command` | 对画布应用明确的修改命令 | 写入前询问 |
| `cinema_create_storyboard` | 创建或更新分镜结构 | 写入前询问 |

“读取概要”不会授权后续写入。收到写入审批时，应检查目标工作区、将改变的节点和素材路径，再决定是否继续。

## 推荐的任务写法

- “读取当前 Cinema 项目概要，只汇报缺失素材和断开的节点，不要修改文件。”
- “根据 `prompts/brief.md` 创建六镜头分镜，先展示计划；写入画布前让我确认。”
- “把这三张参考图加入 Image 节点，并连接到对应的 Text 镜头说明，不要启动生成。”
- “检查 `.anybox-cinema/canvas.json` 是否只包含 Text、Image、Video、Audio 节点，发现问题时先报告。”
- “为已确认的两个镜头准备生成任务；需要选择供应商或产生费用前停下来。”

把“是否允许写入”“是否立即生成”“费用或外部发送前是否停止”写进请求，可以避免项目编排和实际生成被误认为同一个动作。

## 权限、凭据与数据边界

- 项目概要读取属于只读操作；修改画布和创建分镜属于本地写入，需要单独审批。
- 素材、提示词、画布和事件记录默认留在项目文件夹中，但你选择执行生成时，相关输入会发送给已配置的模型供应商。
- 供应商凭据保存在 Anybox 的凭据系统中，不应出现在 `providers.json`、提示词或项目日志里。
- Cinema 本身不替你购买额度、开通账号或绕过供应商的内容政策。
- 在生成、覆盖素材、批量改写画布或导出前，检查审批卡片中的目标项目和影响范围。

## 常见问题

### 项目没有 Cinema 结构

确认插件已为当前项目启用，然后要求 Agent 初始化或修复 Cinema 项目。初始化可以安全重跑，只会补充缺失的受管文件和目录。

### JSON 文件无效

Agent 不会自动覆盖无效 JSON。先备份文件，再修复语法或明确授权从可恢复的信息重建；完成后重新读取项目概要。

### 画布出现不支持的节点

将节点改为 `Text`、`Image`、`Video` 或 `Audio`。让 Agent先报告未知类型和引用位置，不要直接删除承载用户内容的节点。

### 画布有了，但没有生成视频

这是预期边界。Cinema 负责项目和画布编排；实际生成需要 Anybox 中可用的 Cinema Runtime 与已经配置的供应商。确认账号、额度和模型能力后，再明确要求启动生成。

### 素材移动后无法找到

让 Agent 重新读取项目并检查节点中的相对路径。优先在项目目录内整理素材，避免把项目依赖在随时会变化的临时下载路径上。

## 与其他插件配合

- 使用「构建 Web 应用」制作项目展示页、素材审核台或交付页面。
- 使用 Chrome 检查 Web 预览、供应商后台或已登录的发布页面。
- 只有必须操作原生桌面创作软件时，才使用 Windows 电脑控制。
