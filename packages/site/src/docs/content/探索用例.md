# 使用场景

选择结果可验证、范围清晰的任务，并在开始时说明允许读取和修改的内容。

## 软件开发

- 解释目录结构和关键模块。
- 根据错误日志定位代码。
- 补充测试或重构局部模块。
- 汇总变更并准备提交说明。

> 阅读项目入口和测试配置，只说明结构，不要修改文件；最后列出三个优先风险。

## 研究与办公

- 整理会议记录或调研材料。
- 比较方案的目标、成本和风险。
- 从表格与文本中提取可核对的结论。
- 生成提纲、方案或行动清单。

> 阅读 `research` 目录，按“事实、分歧、缺失信息、下一步”整理 Markdown 摘要，不要访问目录外文件。

## 内容创作

- 根据已确认事实编写网页或文档。
- 将大纲扩展为文章、脚本或演示结构。
- 比较表达方向并持续修订项目文件。

> 根据当前目录的产品说明写一版克制的中文介绍；不要补写未知功能，待确认内容单独列出。

## 写好任务

一条有效请求应包含：

1. **目标**：最终要解决什么问题。
2. **范围**：可访问哪些文件，是否允许修改或访问外部服务。
3. **交付物**：需要的格式、路径或呈现方式。
4. **完成标准**：用测试、对比或人工核对判断结果。

复杂任务可先要求只读分析，再单独授权写入。发布内容前应核对名称、数字、链接和能力边界；删除、覆盖、发送或发布操作应采用更小的授权范围。
