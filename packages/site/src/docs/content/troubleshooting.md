# 排障

先保留原始错误，再判断失败发生在项目、会话、Agent、模型、工具、权限还是外部连接。每次只修改一项设置。

## 基本步骤

1. 记录操作系统、Anybox 版本、项目路径、会话、模型和原始错误。
2. 确认当前项目、会话、Provider 和模型正确。
3. 判断问题发生在发送前、模型请求中还是工具调用中。
4. 检查是否有待处理的权限请求。
5. 用最小只读任务复现；仍失败时再重启相关服务。

截图、日志和报告中不要包含密钥、令牌、密码或私人文件内容。

## 常见问题

| 现象 | 检查 |
| --- | --- |
| 项目或会话缺失 | 目录是否存在、可访问，项目分组是否正确；先不要清空数据 |
| 消息无回复 | 会话、Provider、模型和连接错误；运行中任务不要重复发送 |
| 模型不可用 | 凭据、额度、网络、模型 ID、区域和速率限制 |
| Agent 找不到文件 | 活动项目、相对路径、文件是否改名，以及读取工具是否可用 |
| 工具不可见 | 是否保存开关、Agent 策略、只读限制和平台注册表 |
| MCP 工具缺失 | 连接认证、诊断、项目归属和渐进式工具搜索 |
| 权限一直等待 | 活动会话、Agent 连接和上次提交错误；必要时拒绝并缩小请求 |
| 文件变更不符 | 立即停止写入，用变更视图或版本控制确认范围并保留重要工作 |
| 长会话偏离目标 | 重述目标与未完成项，把无关工作移到新会话；压缩不能修复错误事实 |

## 报告问题

提供版本、操作系统、最小复现步骤、预期结果、实际结果和脱敏错误。优先使用最小示例项目。

不要把清空数据、删除配置或重装作为第一步；这些操作可能移除会话和本机配置，应先确认影响并备份。
