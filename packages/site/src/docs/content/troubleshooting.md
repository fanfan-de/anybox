# 排障

排障的目标不是一次更改很多设置，而是先确认失败发生在哪一层：项目、会话、Agent 服务、模型供应商、工具、权限或外部连接。

## 这页的用途

本页提供一条从低风险检查开始的排障路径。先保留错误信息和当前上下文，再逐项缩小范围。

## 开始前记录

在重试或重启之前，记下：

- 操作系统、Anybox 版本、活动项目及目录。
- 活动会话、所选模型和失败操作的原始错误。
- 最近一次成功操作，以及刚修改过的 Provider、工具、权限、MCP 或插件配置。

不要在截图、日志或问题报告中暴露 API Key、访问令牌、密码、私人文件内容或完整认证请求。

## 推荐排障步骤

1. 确认当前项目、会话、Provider 和模型是否正确。
2. 判断问题发生在发送前、模型请求中还是工具执行中。
3. 检查界面是否仍有等待处理的权限请求。
4. 用一个最小只读任务复现问题。
5. 每次只修改一个相关设置，然后再次验证。
6. 问题仍然存在时，再重启桌面应用或对应外部服务。

## 常见现象

### 项目或会话没有出现

- 确认目录可访问，且没有被移动或删除。
- 检查是否切换到了另一个项目分组。
- Agent 服务恢复连接后，等待列表重新读取；不要先清空应用数据。

### 消息无法发送或没有回复

- 确认已选择会话、Provider 和模型，并查看连接错误。
- 用“说明当前项目名称”这类短只读请求测试基本链路。
- 任务仍在运行时，等待或使用明确停止操作，不要重复发送。

### 模型不可用

- 检查 API Key、供应商额度和当前网络。
- 确认模型 ID 仍由该供应商提供。
- 外部 Agent 服务还需检查地址和认证，再用短请求验证。

### Agent 找不到预期文件

- 核对活动项目目录、文件位置以及是否改名。
- 检查读取或搜索工具是否可用。
- 给出项目根目录下的明确相对路径，不要改开过大的上级目录。

### 工具已启用但 Agent 看不到

- 确认工具页面的更改已经保存。
- 检查 Agent 策略、只读会话限制和当前平台。
- 工具注册随本地或 SSH 工作区变化，以运行时注册表和输入 Schema 为准。

### MCP 工具没有立即出现

- 在连接页面检查服务认证和诊断结果。
- 确认服务属于当前项目、当前任务或可渐进发现的来源。
- 延迟工具可能需要先被工具搜索发现；服务变化后重新核对名称。

### 权限请求一直等待或提交失败

- 确认请求属于活动会话，Agent 服务仍然连接。
- 阅读失败提示后再提交，不要连续选择多个决定。
- 必要时拒绝原请求，让 Agent 用更小、更明确的参数重试。

### 文件变更与预期不一致

- 停止继续写入，检查当前项目和最近工具记录。
- 在变更视图或版本控制中确认受影响文件。
- 先保留需要的工作，再用项目自己的恢复方式处理。

### 长会话开始偏离目标

- 重述目标、已确认决策和未完成步骤，把无关任务移到新会话。
- 主会话空闲且历史足够时，可用压缩命令处理更早上下文。
- 压缩不能修复错误事实；发生冲突时以最近明确要求为准。

## 成功表现

- 最小只读请求可以稳定完成。
- 当前项目、会话、Provider 和模型与预期一致。
- 工具或连接能够列出实际可用能力。
- 权限决定只影响对应请求，修复后原步骤可以稳定复现。

## 数据与权限影响

日志、错误详情和工具输入可能包含路径、命令、服务地址或项目片段。分享前应删去密钥、令牌、个人信息和不必要的业务内容。

不要把清空数据目录、删除配置或重新安装作为第一步。这些操作可能移除会话状态或本机配置，应先确认影响并保留备份。

## 常见问题

### 应该先重装吗？

通常不需要。先判断问题属于配置、连接、权限还是单个项目；重装不会修复无效凭据或供应商网络问题。

### 报告问题时应该提供什么？

提供版本、操作系统、复现步骤、预期结果、实际结果和已脱敏错误。能用最小项目复现时，不要提交真实业务仓库。

## 下一步

模型问题查看“模型供应商”，工具和 MCP 问题查看“工具系统”，阻塞执行查看“权限与审批”。仍无法解决时，携带脱敏后的最小复现信息到项目问题反馈渠道。
