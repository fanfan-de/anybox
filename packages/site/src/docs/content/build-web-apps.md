# 构建 Web 应用

`build-web-apps` 是一组前端开发 Skills，覆盖产品定义、界面实现、浏览器验收和 React 优化，并按需提供 shadcn/ui、Stripe 与 Supabase/Postgres 实践。

> 它提供工作流，不提供托管、账号或生产环境访问。文件、命令、浏览器和外部服务仍取决于当前工具与权限。

## 安装与适用范围

在“插件”中安装 `build-web-apps` 并为当前项目启用。需要真实页面验收时，同时启用 Chrome 并启动开发服务器。

适合新建页面、实现完整用户流程、按设计稿重做界面、修复交互与响应式问题，以及优化 React 性能。小范围文案或样式修复应直接沿用现有设计系统。

## 包含的 Skills

| Skill | 作用 |
| --- | --- |
| `frontend-app-builder` | 从需求与设计方向推进到可运行前端 |
| `frontend-testing-debugging` | 检查页面、控制台、交互与响应式表现 |
| `react-best-practices` | 优化请求、渲染和包体积 |
| shadcn/ui | 组合与定制组件 |
| Stripe | 支付、Webhook 和服务端边界 |
| Supabase/Postgres | Schema、查询、索引与 RLS |

这些能力按任务选用，不要求迁移现有组件库，也不会自动连接账号。

## 推荐工作流

1. **定义结果**：说明用户、核心动作、必需内容和完成标准。
2. **检查项目**：读取框架、脚本、组件、样式 token 和现有页面。
3. **实现**：复用既有架构；安装依赖或修改构建配置前说明影响。
4. **验证**：运行类型检查与测试，并在真实页面检查控制台、目标交互、桌面和窄屏布局。
5. **交付**：列出改动、验证结果和仍需人工配置的内容。

示例：

> 在当前 Vite + React 项目实现插件文档首页，保留路由和品牌色；桌面使用侧栏，窄屏使用选择器。用 Chrome 验证搜索和两种视口，不要部署。

## 外部服务边界

- Stripe 和 Supabase Skills 只提供实现指导，不授予凭据或生产访问。
- 密钥应进入安全配置，不得写入源码、Markdown、截图或提交。
- 数据库迁移、真实付款、生产写入、部署和发布必须单独指定环境并确认。
- 构建成功只证明可以编译，不能替代布局和交互检查。

安装后没有新工具属于正常现象：这是 Skill 集合，不包含独立 MCP 或 Connector。
