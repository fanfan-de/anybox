# Skills

Skill 是提供给 Agent 的可复用说明与配套资源，适合保存项目规范、发布流程、测试约定、检查清单和特定工具的使用方式。它帮助 Agent 在需要时加载正确做法，但不会绕过工具权限。

## 打开 Skills 工作台

从桌面端侧栏打开 **Skills**。工作台分为三个主要区域：

- **本地**：查看和编辑用户或项目中的 Skill；插件提供的 Skill 会以只读方式显示。
- **发现**：搜索外部 Skill 来源并检查说明、文件、版本和安全信号。
- **已下载**：管理受管 Skill 的启用状态、更新、已安装版本、回滚和本地 Fork。

## 四类来源

Anybox 会按当前项目汇总不同来源的 Skill：

| 来源 | 典型位置或条件 | 适合内容 |
| --- | --- | --- |
| 项目级 | `<项目>/.anybox/skills/<名称>/SKILL.md` | 当前仓库的构建、测试和架构规则 |
| 用户级 | `~/.anybox/skills/<名称>/SKILL.md` | 个人跨项目复用的工作方式 |
| 插件 | 已安装、启用并被项目选中的插件 | 插件配套操作说明和资源 |
| 受管下载 | “发现”或 URL 安装后进入“已下载” | 第三方或 Registry 分发的版本化 Skill |

项目级规则通常比个人通用习惯更适合描述仓库命令。不要在用户级 Skill 中写死只对一个项目有效的绝对路径。

## 创建本地 Skill

1. 打开 **Skills → 本地**。
2. 选择添加或新建 Skill，并决定保存到用户级还是当前项目。
3. 填写清晰的名称、触发说明和步骤。
4. 保存后确认列表中出现该 Skill，且预览能正确显示 `SKILL.md`。
5. 在新会话中提出符合触发条件的任务，观察 Agent 是否先加载 Skill 再执行。

也可以通过“从本地文件导入”选择现有 `SKILL.md`，或打开文件位置后用编辑器维护资源文件。

## 推荐结构

```md
---
name: release-check
description: 发布前检查构建、测试、版本与产物。
---

# Release Check

在准备正式发布时使用。

1. 读取仓库中的发布说明。
2. 运行类型检查和测试。
3. 构建并核对产物。
4. 在发布前汇报版本号、风险和未完成项。
```

名称和描述应帮助 Agent 判断何时使用；正文应给出顺序、成功条件、停止条件和相关资源。一个 Skill 聚焦一类流程，比把全部团队规则塞进一个长文件更容易维护。

## 下载与启用受管 Skill

1. 在 **发现** 中搜索，或使用“从 URL 安装”。搜索和下载会访问外部服务。
2. 阅读概览、README、文件列表、版本记录和 Security 页面。
3. 下载后前往 **已下载**；下载内容保存在受管区域，默认不会被 Agent 加载。
4. 打开“允许 Agent 使用”后，再确认目标项目的 Skill 选择包含它。
5. 用只读任务验证 Skill 的触发和说明是否符合预期。

“已下载”不等于“已启用”，“已启用”也不等于已经执行。Agent 只会先看到可发现摘要，并在任务需要时加载完整内容。

## 安全边界

- Skill 是说明和资源，不会凭自身直接执行代码；实际操作仍通过工具或 MCP，并接受项目边界和权限策略检查。
- 不要在 `SKILL.md`、示例、脚本参数或附属文件中保存 API Key、Token、私人账号或客户数据。
- 外部来源可能携带误导指令、过时命令或危险资源，安装前应审阅内容和发布者。
- Anybox 会检查下载地址、包大小、路径、符号链接、完整性及可用的上游扫描信号。
- “扫描正常”只表示没有发现已知风险，不是绝对安全保证；被阻止的版本不能下载或更新。
- 插件 Skill 由插件包管理，在本地视图中只读；要修改时可新建本地 Skill，而不是改受管来源。

## 更新、回滚与 Fork

- 在 **已下载** 中选择“检查更新”，先查看版本和文件变化预览。
- 更新会重新下载并重新扫描；安全策略阻止的版本不会生效。
- Anybox 保留已安装版本时，可以从版本列表回滚；失效的项目选择可能被清理。
- “Fork 到本地”会复制为可编辑本地 Skill，后续不再等同于上游受管版本。
- 禁用或删除受管 Skill 会从 Agent 的可发现列表移除，并清理引用它的项目选择。

## 数据与网络影响

本地 Skill 保存在用户目录或项目目录；项目级 Skill 如果提交到 Git，会随仓库共享。发现、下载、查看上游信息和检查更新会访问相应 Registry 或托管站点。

当 Agent 加载 Skill 时，其说明和被读取的资源会进入当前会话上下文；如果随后调用云端模型，相关上下文也会发送给当前模型服务商。

## 排错

- 列表中没有本地 Skill：确认目录中存在名为 `SKILL.md` 的文件，并重新打开项目或刷新工作台。
- 下载后 Agent 不使用：到“已下载”启用它，并检查当前项目的 Skill 选择。
- 插件 Skill 不出现：确认插件已安装、启用，并被当前项目选择。
- 更新被阻止：查看 Security 中的风险原因，不要通过复制受阻包来规避检查。
- Skill 经常误触发：收窄 description，明确适用任务与不适用场景。
- Agent 忽略某一步：把成功条件、依赖命令和必须停止确认的条件写得更具体。

## 下一步

先为当前项目创建一个只读检查 Skill，验证触发和资源加载；确认稳定后，再逐步加入测试、构建或发布流程。需要访问外部系统时，另外配置受权限控制的 MCP 或插件。
