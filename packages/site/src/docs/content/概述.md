# 产品概览

第一句就是我的。

Anybox 是面向本地项目的开源 AI Agent 桌面工作台。它把项目文件、会话、模型、工具调用与权限确认放进同一个可检查的工作空间，让 Agent 不只回答问题，也能围绕真实项目持续推进任务。

## Anybox 的用途

Anybox 适合需要结合真实文件、持续上下文和可执行工具的工作。你可以让 Agent 阅读项目、检索信息、运行命令、修改内容，再在同一条会话中检查过程与结果。

常见方向包括：

- 软件开发：理解代码、定位问题、补充测试、重构模块并整理交付说明。
- 研究与办公：整理资料、比较信息、分析数据并形成方案或行动清单。
- 内容与创作：从想法出发，生成文案、脚本、页面草稿和项目计划。

具体能力会随当前操作系统、工作区、模型、已启用工具、MCP 连接和插件而变化。

## 核心工作方式

Anybox 围绕项目和会话组织工作：

- 项目提供文件目录和工作边界。
- 会话保存一次持续的 Agent 协作过程。
- 模型负责理解目标并生成下一步。
- 工具负责读取、搜索、执行或修改。
- 权限流程在需要时暂停执行，等待你确认。
- Skills 与插件为重复工作提供额外规则和能力。

## 开始一个任务

1. 打开一个你了解的本地项目目录。
2. 在设置中连接模型供应商并选择模型。
3. 新建会话，说明目标、限制条件和预期结果。
4. 观察回复、工具调用、命令输出和文件变更。
5. 遇到权限请求时，先检查对象、路径、命令和风险。
6. 根据结果继续补充要求，或在确认无误后结束任务。

第一次使用时，建议先从只读任务开始，例如请 Agent 说明项目结构或查找某个配置入口。

## 成功表现

一次健康的 Anybox 工作流通常具有这些表现：

- Agent 能说明它正在处理哪个项目和目标。
- 工具调用与结果出现在当前会话中，可以按需检查。
- 需要写入或执行敏感操作时，会出现明确的权限决策点。
- 最终回复说明已完成内容、未完成内容和需要你确认的事项。
- 切换会话后，既有会话历史仍可重新查看。

结果是否正确仍需要你根据项目目标、测试结果和业务要求判断。

## 数据与权限影响

打开项目会让该目录成为当前工作的上下文，但不代表所有操作都自动获准。工具是否可见、Agent 策略、会话限制和调用级权限会共同决定一次操作能否执行。

如果使用云端模型或外部 MCP 服务，相关请求可能离开本机。发送前应检查服务地址、认证方式以及任务中是否包含不应共享的内容。

不要把 API Key、访问令牌、密码或私人账号信息直接写进会话、项目文件、Skill 或插件示例。

## 常见问题

### Anybox 只是聊天应用吗？

不是。会话是交互入口，项目上下文、工具执行、权限审批和变更检查共同构成完整工作流。

### Anybox 会自动修改项目吗？

只有在当前任务使用了写入能力且通过相关限制时，文件才可能被修改。执行前说明只读要求，并在执行后检查变更。

### 所有任务都必须使用同一个模型吗？

不必。可以按任务的复杂度、上下文长度、成本和供应商可用性选择模型。

### 所有数据都会留在本机吗？

不能一概而论。本地项目文件位于你的工作区，但云端模型、远程 Agent 服务或外部连接可能接收任务所需的数据。
