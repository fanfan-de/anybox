# Use Cases

Choose a verifiable, well-scoped task and state what the agent may read or change before it begins.

## Software Development

- Explain the directory structure and key modules.
- Trace an error to the relevant code.
- Add tests or refactor a local module.
- Summarize changes and prepare a commit description.

> Read the project entry points and test configuration. Explain the structure without modifying files, then list the three highest-priority risks.

## Research and Office Work

- Organize meeting notes or research material.
- Compare goals, costs, and risks across options.
- Extract verifiable findings from tables and text.
- Produce an outline, proposal, or action list.

> Read the `research` directory and create a Markdown summary of facts, disagreements, missing information, and next steps. Do not access files outside that directory.

## Content Creation

- Write pages or documentation from confirmed facts.
- Expand an outline into an article, script, or presentation structure.
- Compare directions and revise project files through feedback.

> Use the product notes in this directory to draft restrained Chinese copy. Do not invent unsupported capabilities; list claims that still need confirmation separately.

## Write an Effective Task

Include four things:

1. **Goal:** the problem to solve.
2. **Scope:** accessible files and whether edits or external services are allowed.
3. **Deliverable:** the required format, path, or presentation.
4. **Completion criteria:** tests, comparisons, or manual checks that prove the result.

For complex work, request read-only analysis before authorizing writes. Verify names, numbers, links, and capability boundaries before publishing, and use narrower approval for deletion, overwrite, sending, or publication.
