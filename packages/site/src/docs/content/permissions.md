# 权限与审批

权限系统决定一次具体操作能否执行。它与工具页面的启用开关相关，但不是同一件事：工具已启用，只表示它可以进入 Agent 的能力计划，不表示每次调用都会自动通过。

## 这页的用途

本页说明权限请求何时出现、应该检查什么、不同决策的范围，以及拒绝请求后如何安全地继续任务。

## 一次调用会经过哪些边界

| 层级 | 作用 |
| --- | --- |
| 全局工具选择 | 决定某项内置工具是否可供后续任务使用 |
| Agent 工具策略 | 通过允许、拒绝或只读规则进一步缩小能力 |
| 会话策略 | `session.policy.toolPolicy` 可限制任意会话使用修改能力 |
| 调用级权限 | 根据当前工具、参数、路径、命令和风险作出决策 |
| 工具自身守卫 | 校验输入 Schema、路径边界和运行条件 |

任何一层拒绝或校验失败，都可能使调用无法执行。

## 何时会看到权限请求

当运行时无法安全地自动决定一次操作时，会话会显示阻塞式权限请求。请求可能来自 Shell、写入工具、浏览器或插件动作，也可能来自需要外部数据访问的能力。

请求会尽可能提供：

- 操作标题和摘要。
- Agent 提出的理由。
- 风险等级。
- 工作目录或目标路径。
- 将要运行的命令。
- 发送或修改的正文。

并非每个请求都有全部字段。缺少判断所需的信息时，可以拒绝并要求 Agent 用更小、更明确的动作重试。

## 审批步骤

1. 确认请求属于当前会话和当前目标。
2. 检查工具名称、操作摘要和 Agent 理由。
3. 阅读路径、工作目录、命令或外部目标。
4. 判断动作是否会删除、覆盖、发布或发送数据。
5. 选择当前请求提供的最小授权范围。
6. 等待会话恢复，并检查实际工具结果。
7. 对写入操作继续检查文件变更或项目验证结果。

不要只因为 Agent 推荐某个决定就直接批准。审批是用户对具体动作和范围作出的判断。

## 决策范围

界面只会显示当前请求允许的选项，常见选项包括：

- 拒绝：不执行当前操作。
- 允许一次：只批准这一次请求。
- 本会话允许：在当前会话和对应范围内复用授权。
- 允许：确认当前集成提供的请求；具体范围以界面说明为准。

风险较高或包含敏感输入的请求可能只允许一次性决定。看不到“本会话允许”时，不应通过重复操作绕过限制。

## 成功表现

- 权限卡片明确显示待决、已允许、已拒绝或失败状态。
- 允许后，原任务从阻塞点继续，而不是创建一项无关操作。
- 拒绝后，Agent 不执行被拒绝的动作。
- 工具结果说明实际执行了什么，并与请求范围一致。
- 文件或外部数据发生变化时，可以找到对应的执行记录。

## 数据与权限影响

“只读”描述的是工具意图，不一定意味着数据不会离开设备。读取结果可能进入当前模型上下文，远程 MCP 或 Connector 还可能把参数发送给外部服务。

“本会话允许”不是永久授权，也不是操作系统权限。它只适用于运行时记录的当前会话和匹配范围；新会话、不同路径或不同操作仍可能再次询问。

关闭工具不会撤销第三方服务本身的账号授权。需要撤销外部访问时，还应在对应连接或服务中处理凭据。

## 常见问题

### 工具已启用，为什么仍然询问？

启用状态只控制可用性。调用级权限仍会根据真实参数、路径、命令和风险重新评估。

### 拒绝后任务会怎样？

被拒绝的操作不会执行。Agent 可能说明无法继续，也可能提出只读或更小范围的替代方案。

### 权限请求一直停留在等待状态

确认请求仍属于活动会话，Agent 服务仍然连接，并检查上一次提交是否显示失败。不要连续点击多个决定。

### 如何降低审批风险？

先执行只读检查，把大动作拆成小步骤，限制路径和命令，并优先选择“允许一次”。
