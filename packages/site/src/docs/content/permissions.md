# 权限与审批

工具“已启用”只表示 Agent 可以使用它，不代表每次调用都会自动通过。一次操作需依次满足以下边界：

| 层级 | 作用 |
| --- | --- |
| 全局工具选择 | 决定内置工具是否可用 |
| Agent 策略 | 通过允许、拒绝或只读规则缩小能力 |
| 会话策略 | 可排除当前会话中的修改操作 |
| 调用级权限 | 根据工具、参数、路径、命令和风险决定 |
| 工具守卫 | 校验输入、路径边界和运行条件 |

任一层拒绝或校验失败，操作都不会执行。

## 审批操作

出现权限卡片时：

1. 确认请求属于当前会话和目标。
2. 检查工具、理由、风险、路径、命令和外部目标。
3. 判断是否会删除、覆盖、上传、发送或发布。
4. 选择最小授权范围，优先“允许一次”。
5. 执行后检查工具结果、文件变更或外部状态。

信息不足时应拒绝，并要求 Agent 用更小、更明确的参数重试。

## 决策范围

- **拒绝**：不执行本次操作。
- **允许一次**：仅批准当前请求。
- **本会话允许**：仅在当前会话和匹配范围内复用。
- **允许**：范围以当前集成的界面说明为准。

高风险请求可能只支持一次性决定。“本会话允许”不是永久授权，也不是操作系统权限；新会话、新路径或不同操作仍可能再次询问。

## 关键边界

- “只读”不等于数据一定留在本机；读取结果可能发送给模型或远程服务。
- 关闭工具不会撤销第三方账号授权，外部凭据需在对应连接或服务中撤销。
- 拒绝后该操作不会执行，Agent 可改用只读或更小范围的方案。
- 权限一直等待时，检查活动会话和 Agent 连接，不要连续提交多个决定。
