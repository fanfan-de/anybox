# 项目、工作区与会话

Anybox 以项目目录作为 Agent 工作的起点，再用会话保存每一次持续协作。理解这三者的关系，可以减少上下文混淆，也能让文件访问和权限判断更容易检查。

## 这页的用途

本页说明如何选择项目、组织会话、判断当前 Agent 正在处理什么，以及在切换任务时保留清晰边界。

## 三个概念

### 项目

项目代表一组相关文件和任务。对本地项目而言，它通常对应你主动打开的目录。项目名称用于识别，目录路径决定工具从哪里开始读取和执行。

### 工作区

工作区是围绕项目展开的桌面工作环境。项目树、会话列表、执行视图和相关面板在这里保持关联。不同类型的工作区可提供不同工具，例如本地目录与 SSH 工作区使用的 Shell 能力并不相同。

### 会话

会话保存一次 Agent 协作过程，包括用户消息、回复、工具轨迹、错误、权限请求和与任务相关的变更信息。同一个项目可以创建多个会话，用来分隔不同目标。

## 打开项目

1. 在 Anybox 中选择打开文件夹。
2. 选择包含任务资料、代码或文档的目录。
3. 确认侧边栏显示了预期的项目名称和路径。
4. 在开始写入前，先让 Agent 只读说明目录结构。
5. 如果路径不对，停止当前任务并切换到正确项目。

选择过大的上级目录会扩大可检索范围，也会增加噪声。优先打开能够完整承载任务的最小合理目录。

## 创建和组织会话

1. 在目标项目下新建会话。
2. 用第一条消息写清任务目标、允许范围和完成标准。
3. 为不相关的目标创建不同会话。
4. 继续既有工作时，先查看最近消息和未完成事项。
5. 切换模型或工具配置后，在会话中说明变化对任务的影响。

推荐让一个会话围绕一个稳定目标展开，例如“修复登录错误”或“整理发布说明”，而不是把多个无关任务连续堆在同一段历史中。

## 在会话中检查执行

ThreadView 是执行记录视图，不只是聊天窗口。它会把最终回复作为主要内容，并按需呈现推理摘要、工具调用、来源、权限、文件变更、工作流状态和错误。

已完成的工具和推理内容可能被弱化或折叠。需要核对时展开对应项目，不要只根据最终回复推断文件是否真的改变。

## 成功表现

- 当前项目名称和目录与任务资料一致。
- 新会话出现在正确项目下。
- Agent 能从当前目录找到预期文件。
- 工具轨迹和最终回复属于同一任务。
- 切换到其他会话再返回后，既有历史仍可查看。
- 任务完成后，结果和待办可以从会话中快速定位。

## 数据与权限影响

项目文件仍受文件系统权限和 Anybox 工具边界约束。打开目录只是建立工作上下文，不代表 Agent 可以执行目录中的任意命令或修改所有文件。

会话历史由 Anybox Agent 保存，用于重新加载和继续工作。长会话可能使用上下文压缩来构建后续模型请求，但这不等同于删除原始项目文件。

使用云端模型时，进入模型上下文的消息和选定文件内容可能发送到对应供应商。SSH 工作区和外部连接还受远程主机及服务自身权限控制。

## 常见问题

### Agent 找不到文件

先确认活动项目目录是否正确，再检查文件是否位于该目录、工具是否启用，以及任务是否误用了另一个会话。

### 应该继续当前会话还是新建会话？

目标、资料范围和完成标准基本一致时可以继续。目标明显变化或需要不同权限边界时，建立新会话更清晰。

### 切换会话会停止正在运行的任务吗？

不要把界面切换当作停止操作。任务仍在运行时，应使用当前界面提供的明确停止动作并等待状态更新。

### 会话越长越好吗？

不一定。长会话有助于延续决策，但无关历史会增加噪声。保持单一目标，并在任务阶段明显变化时新建会话。
