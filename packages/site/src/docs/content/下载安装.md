# 快速开始

Anybox 是面向本地项目的 AI Agent 桌面工作台。你可以打开一个目录或 Git 仓库，在持久会话中让 Agent 阅读代码、制定计划、调用工具并跟踪结果。

## 安装前确认

桌面端当前处于 Early Access，主要目标平台如下：

| 平台 | 当前状态 | 发布形式 |
| --- | --- | --- |
| Windows x64 | Early Access | Windows 安装包 |
| macOS Apple Silicon | Early Access | macOS 安装包 |
| Linux x64 | Early Access | AppImage；部分版本同时提供 Debian 包 |
| Android | 开发与早期测试 | 是否有可安装包以 GitHub Releases 为准 |

iOS 与 Android 客户端源码仍在持续开发。移动端是否公开发布、支持哪些系统版本，应以对应 Release 的说明和资产为准。

如果系统显示安全确认，请核对发布者、版本号和校验信息，并确认安装包来自项目的 GitHub Releases 页面。

## 安装桌面端

1. 打开 Anybox 项目的 GitHub Releases。
2. 选择最新版本，再检查该版本是否包含你的平台与架构。
3. 下载对应安装包；不要把其他架构的包当作兼容版本安装。
4. 按操作系统提示完成安装并启动 Anybox。
5. 首次启动后保留默认本地 Agent 设置，先完成一次最小连接验证。

安装成功后，你应能看到工作台、项目侧栏和新建会话入口，而不是只停留在安装器或空白窗口。

## 打开第一个项目

1. 在项目侧栏选择“打开文件夹”。
2. 选择一个你有权限读写的本地目录或 Git 仓库。
3. 等待项目出现在侧栏，并确认显示的路径正确。
4. 如需连接服务器目录，使用“打开远程文件夹”并配置 SSH 连接，不要把远程路径当作本地路径填写。

成功时，项目下会出现会话区域；Git 项目还可在后续按需创建独立 worktree。

## 连接模型

1. 打开“设置 → 服务商”。
2. 选择服务商并按界面提示登录或填写 API Key。
3. 点击“测试连接”，确认设置页显示连接成功。
4. 打开“设置 → 模型”，选择主模型；需要时再设置小模型。
5. 返回项目，新建一个会话。

服务商目录和模型列表会动态更新。如果刚配置的模型没有出现，先刷新服务商目录，再回到模型页面检查。

## 完成第一次会话

建议先从只读任务开始，例如：

```text
请先阅读这个项目的 README 和目录结构，说明它如何启动；暂时不要修改文件。
```

你应能看到 Agent 的回复、工具调用过程和最终结论。确认项目与模型都正确后，再尝试修复、重构或生成文件等写入任务。

## 权限与数据影响

- 默认模式会根据工具、命令、路径和风险判断自动运行、询问或拒绝，并非每次写入都会弹出审批。
- Critical 风险、活动项目边界之外的副作用操作，以及部分敏感路径操作会被阻止；完全访问模式也不会绕过这些边界。
- Side Chat 是只读辅助会话；Planning 模式在计划获批前阻止有副作用的工具。
- 项目、会话、任务、审批记录和多数运行状态保存在本机 Agent 数据目录。
- 调用模型服务商时，Prompt、会话上下文及任务需要的文件或工具内容会发送到所选服务商。
- MCP、Connector、Web Fetch、插件或 Skill 市场，以及移动端云中继，也可能产生外部网络请求。

## 常见启动问题

- 窗口打开但 Agent 不可用：默认本地服务地址为 `http://127.0.0.1:4096`，健康检查为 `/healthz`；检查端口占用和安全软件拦截。
- 只看到示例或无法创建真实会话：等待托管 Agent 启动，或检查自定义 Agent 地址是否正确。
- 模型测试失败：检查凭据、账户额度、网络代理、API Base URL 和模型是否仍可用。
- 项目无法打开：确认目录存在、当前账户有权限，并检查是否误选了文件而非文件夹。
- 下载页没有目标平台：该版本可能未发布对应资产，请查看其他最新 Release，不要假定所有版本都包含所有平台。

## 下一步

模型连接成功后，继续阅读“模型供应商”了解动态目录和自定义端点，再阅读“Skills”把项目规范与重复流程沉淀为可复用说明。
