# 模型供应商

Anybox 通过 Provider 连接模型服务，再由 Model 决定一次会话实际使用的能力、上下文窗口和计费方式。Provider 与 Model 分开配置，便于在同一项目中切换不同服务。

## 配置入口

- 打开“设置 → 服务商”管理登录、API Key、API Base URL 和连接测试。
- 打开“设置 → 模型”选择全局主模型与小模型，并查看已连接服务商暴露的模型。
- 在会话顶部切换模型，可让当前会话覆盖全局选择，而不影响其他会话。

服务商和模型目录会动态更新。页面显示的模型、能力、状态与价格元数据可能随 models.dev、服务商接口和 Anybox 版本变化，不应把某份静态名单视为长期保证。

## 连接第一个服务商

1. 打开“设置 → 服务商”。
2. 从左侧列表选择服务商；可以按名称、能力或连接状态搜索和筛选。
3. 按该服务商提供的方式登录或填写 API Key。
4. 如需使用代理、私有网关或兼容服务，填写自定义 API Base URL。
5. 保存设置后点击“测试连接”。
6. 测试成功后打开“设置 → 模型”，选择主模型。
7. 返回项目，新建一个只读会话验证完整链路。

成功时，服务商会显示已连接状态，连接测试返回成功，并且 Models 页面能看到它暴露的可用模型。

## 支持的连接方式

具体方式以服务商页面为准，常见入口包括：

- Anybox 账户：在系统浏览器中完成登录。
- OpenAI：ChatGPT Pro/Plus 浏览器登录、设备码登录或 API Key。
- 其他目录服务商：通常使用 API Key，也可按目录提示使用相应环境变量。
- 自定义服务商：使用自定义端点、API Key 和模型 ID。

浏览器或设备码登录完成后应返回 Anybox 查看最终状态。仅关闭浏览器页面不代表桌面端已经取得可用会话。

## 选择模型

模型页面会显示目录提供的能力标签，例如推理、工具调用、视觉或图像输出，以及上下文和输出限制等信息。

- 主模型用于常规会话。
- 小模型可用于标题生成等轻量任务；不配置时由当前设置决定回退方式。
- 推理强度只对支持该能力的模型生效。
- 已弃用、未连接或服务商未暴露的模型不适合作为默认值。

先用日常模型完成只读验证，再为长上下文、复杂重构或多模态任务选择更合适的模型。

## 添加自定义端点

1. 在服务商页面选择“添加自定义服务商”。
2. 填写清晰且稳定的服务商名称。
3. 填写完整 API Base URL，并确认它与目标服务的兼容协议一致。
4. 按需要填写 API Key、默认模型与聊天端点。
5. 保存后立即运行“测试连接”。

自定义端点也可指向团队网关或本机运行的兼容服务，但 Anybox 本身不内置本地模型推理引擎。端点的鉴权、日志、留存和网络暴露由该服务负责。

## 凭据与数据边界

- 不要把 API Key 写入项目文件、Skill、Prompt 或 Git 仓库。
- 手动保存的 Provider 凭据位于本机 Agent 管理的应用数据中，并在系统支持时收紧文件访问权限。
- 这不等同于承诺使用操作系统钥匙串、硬件保护或额外文件加密；高安全要求环境应优先使用受控环境变量、受保护账户或独立 Agent 部署。
- 如果页面提示可使用环境变量，请使用该服务商显示的变量名，不要把值粘贴进仓库配置。
- “测试连接”会向服务商或自定义端点发送验证请求。
- 正式会话会把 Prompt、所需上下文以及 Agent 选择提交的文件或工具内容发送给当前模型服务。

切换到自定义或外部 Agent 服务时，还要核对服务地址的网络可见性、TLS、认证和团队数据政策。

## 排错

- 没有可选模型：先确认服务商已连接，再刷新服务商目录并返回 Models 页面。
- API Key 被拒绝：检查是否复制完整、是否过期、账户是否有额度，以及 Key 是否允许目标模型。
- 浏览器登录停在“连接中”：回到 Anybox 查看状态；必要时断开后重新发起登录或改用设备码。
- 自定义端点返回 404：检查 Base URL 是否多写或少写了 API 路径，并确认协议兼容。
- 测试连接成功但会话失败：检查具体模型 ID、上下文限制、区域限制、速率限制和服务商运行状态。
- 目录刷新失败：保留已有缓存稍后重试，并检查代理、防火墙和系统时间。
- 当前会话仍用旧模型：检查会话级模型覆盖，而不只是全局 Models 设置。

## 下一步

连接稳定后，用只读任务比较模型的速度和工具调用表现，再阅读“Skills”配置项目规范。需要访问外部系统时，再按最小权限原则添加 MCP 或插件。
