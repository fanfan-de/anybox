# 模型供应商

Provider 负责连接模型服务，Model 决定会话使用的能力、上下文与计费方式。

## 配置模型

1. 打开“设置 → 服务商”，选择服务商并登录或填写 API Key。
2. 如使用代理、团队网关或兼容服务，填写 API Base URL。
3. 保存并执行“测试连接”。
4. 打开“设置 → 模型”，选择主模型和可选的小模型。
5. 在项目中新建只读会话，验证完整链路。

会话顶部的模型选择可覆盖全局设置。服务商目录会动态更新，静态模型列表不代表长期可用性。

## 选择模型

模型页可能显示推理、工具调用、视觉、上下文和输出限制等能力。

- 主模型用于常规任务，小模型适合标题等轻量工作。
- 推理强度只对支持的模型生效。
- 长上下文、复杂重构或多模态任务应选择对应能力的模型。
- 已弃用、断开或未向当前账户开放的模型不应设为默认。

## 自定义端点

选择“添加自定义服务商”，填写名称、完整 API Base URL、凭据和模型 ID，保存后立即测试。Anybox 不内置本地推理引擎；本机服务、团队网关的鉴权、日志、留存和网络安全由其维护者负责。

## 凭据与数据

- 不要把密钥写入项目、Prompt、Skill 或 Git 仓库。
- 手动保存的凭据位于本机 Agent 管理的数据中；不要假定一定使用系统钥匙串或额外加密。
- “测试连接”和正式会话都会向目标服务发出请求；正式会话还会发送 Prompt、上下文和任务所需的文件或工具内容。

## 排障

- **没有模型**：确认连接成功，刷新目录，再检查模型页。
- **凭据被拒绝**：检查完整性、有效期、额度和模型权限。
- **自定义端点 404**：核对 Base URL 的 API 路径与兼容协议。
- **测试成功但会话失败**：检查模型 ID、上下文、区域、速率限制和会话级覆盖。
