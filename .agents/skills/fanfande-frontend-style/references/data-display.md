# Data Display

## 选择形态

- 少量同类对象：list
- 多列比较：table
- 层级文件/插件/资源：tree
- 视觉模板或插件市场：grid/card
- 当前项详情：detail pane
- 时间过程：timeline
- 执行输出：log viewer/terminal

## List

list row 应有稳定高度、明确 hover/selected/focus 状态、固定图标槽和 action 槽。主文本默认单行，不要在行内做“标题 + 灰色说明”的双行结构。辅助信息移到独立列、右侧 meta 槽、tooltip、详情面板或展开行。

## Table

table 用于比较和扫描。列宽要明确，数字/状态/日期对齐规则稳定。行 hover 不应改变高度。批量选择需要 checkbox 列和明确 selected 状态。

表格单元格默认单行。不要在名称列里堆主标题和副说明；副信息应拆成独立列、图标提示、详情面板或 row expansion。这样表格扫描节奏稳定，也避免行高被个别内容撑开。

状态列优先使用固定尺寸图标，不使用文字 badge。图标用 `aria-label`、`title` 或 tooltip 提供含义；表格需要大量扫描时，图标比文字状态更稳定，不会因为状态文案长短导致列宽和视觉密度变化。

## Tree

tree 用于层级导航。展开箭头、图标、标签、badge、行操作要有固定槽位。缩进一致，长路径省略，当前项清晰。tree row 默认单行，不要把路径说明、状态说明放到第二行。

## Grid

grid/card 用于模板、插件、资源选择等对象浏览。卡片数量多时提供搜索、筛选、排序。不要把管理型数据强行做成大卡片。

## Detail Pane

详情面板显示当前选择的上下文、属性、操作和状态。详情为空时显示轻量空状态，不要让右侧栏空白发散。

## Timeline

timeline 用于任务、构建、自动化、日志事件。时间、状态、标题、详情分层明确。错误和警告使用语义 token。

## Log Viewer

日志区域优先 mono、紧凑行高、可复制、可搜索。长行处理要明确；重要状态可高亮，但不要彩虹式配色。
