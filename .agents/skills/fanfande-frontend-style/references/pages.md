# 页面原型

## Workbench

工作台强调多 pane、tab、工具栏、composer、terminal/log、详情区。使用固定结构和内部滚动。避免大标题和卡片化装饰。

## Dashboard

dashboard 只用于概览和快速行动。指标卡不要过大；图表和列表应服务判断。不要做营销化 hero 或满屏装饰图。

## Settings / Preferences

设置页使用 row-first：分组 panel 内部用设置行，左侧标题/说明，右侧控件。高级配置可以折叠。不要把每个设置项做成独立 card。

## Plugin Marketplace

插件市场需要搜索、筛选、状态、安装操作、详情入口。大量插件优先 list/table 或紧凑 grid。插件卡片要展示名称、作者/来源、状态、简短描述和主操作。

## Plugin Detail

详情页显示插件名称、状态、版本、权限、配置、日志和危险操作。权限和风险信息要清晰，不要藏在长文案里。

## Account / Billing

账户和计费页面要直接、可信、低装饰。重要状态、计划、用量、发票、操作入口清楚。避免营销升级页风格侵入产品设置。

## Empty First Run

首次空状态可以更友好，但仍要产品化。一个标题、一段说明、一个主要动作、一个次要入口足够。

## Logs / Debug Console

调试页面以密度和可复制为主。提供筛选、搜索、清除、导出、级别状态。不要用卡片承载每条日志。

## Import / Export Flow

导入导出是任务流，使用 stepper、检查列表、错误恢复和最终摘要。失败项要可定位、可重试。

## Error / Recovery Page

错误页说明影响、可能原因、可执行操作和技术详情入口。不要只显示“出错了”。
