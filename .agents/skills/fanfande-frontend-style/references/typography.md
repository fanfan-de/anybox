# Typography

## 字体

优先使用项目 token：`--font-sans` 和 `--font-mono`。产品 UI 使用 sans，代码、路径、环境变量、快捷键、日志片段使用 mono。

## 层级

工具型界面避免过大的标题：

- 页面标题：20px 到 24px，少量使用
- section 标题：16px 到 18px
- row/card 标题：14px 到 16px
- 正文：13px 到 15px
- helper/meta：12px 到 13px
- badge/shortcut：11px 到 12px

## 文案密度

界面文案要短，优先动作和状态。不要在工具表面常驻解释“如何使用这个功能”的长段落。复杂说明放到 help text、empty state、tooltip、popover 或文档入口。

## 标题副文案

默认不要在页面标题、section 标题、panel 标题、card 标题下面添加解释性副文案。像“紧凑按钮、输入、选择器和开关。”、“状态反馈靠语义色和明确下一步。”这类描述不应出现在正式 UI 中。

优先让标题本身足够明确，让布局和控件表达含义。只有当缺少说明会导致误操作、权限风险、数据损失或恢复困难时，才保留辅助文案。

## Helper Text

helper text 不是装饰，也不是默认结构。只有这些情况允许常驻：

- 错误原因和修复方向。
- 危险操作、不可逆操作或权限影响。
- 空状态的下一步行动。
- 难以通过 label 表达的业务约束。

普通设置项、普通表格行、普通菜单项和普通 panel 不要带 helper text。说明内容应放到 tooltip、详情区、文档入口或按需展开内容中。

## 行内文字

普通扫描行默认只保留一行主文本。不要在列表行、表格行、设置行、任务行中放第二行灰色说明。行内文字过长时省略，完整内容通过 tooltip、详情面板或展开行查看。

如果需要同时展示名称、位置、时间、频率、计数、状态等信息，优先拆成独立列或右侧 meta 槽，而不是堆在主标题旁边或下一行。

## 中文与英文

中文按钮优先 2 到 4 个字。英文 token、路径、模型名、文件名要允许省略和复制。中英文混排时避免负 letter-spacing，不要用 viewport width 缩放字体。

## 代码与日志

代码块、terminal、日志、diff 使用 mono，行高更紧凑。长行应横向滚动或按上下文折行，不能撑破 pane。日志状态色用语义 token，不用任意鲜艳色。

## 空状态文案

空状态只说当前状态和下一步动作。不要写营销式价值主张。主标题一句，辅助说明一到两句，最多一个主要动作和一个次要动作。
