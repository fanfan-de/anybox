# 总体原则

## 产品气质

Fanfande Studio 的界面应接近“成熟桌面生产力工具”，而不是网页营销产品。视觉要安静、低噪、可长时间停留；交互要稳定、直接、可预测；信息密度要服务工作流，而不是为了显得空旷。

## 设计判断顺序

1. 先判断用户任务：阅读、编辑、比较、选择、配置、调试、管理、确认。
2. 再判断页面密度：工作台和管理界面偏紧凑，配置页偏舒展，首次空状态可稍微引导。
3. 再选择结构：shell、pane、panel、row、list、table、form、dialog。
4. 最后处理视觉：token、色彩、圆角、边框、动效、图标。

## 风格关键词

- 安静：低对比背景、轻边框、少阴影、少装饰。
- 桌面：固定工具区、稳定面板、明确 resize、drag、tab、focus 行为。
- 克制：强调色只用于行动、选中、链接、状态，不做大面积装饰。
- 密度：信息排列紧凑但留出可点击面积，避免“漂亮但低效”的空旷布局。
- 结构化：用分组、标题、行分隔、状态标签表达层级，而不是堆卡片。

## 组件优先级

优先复用目标代码库已有组件和 CSS class。新增组件时，先确认是否能由 button、icon button、input、menu、panel、list row、table row、dialog、toast 等基础形态组合完成。

不要为一次性页面创建过于业务化的基础样式。基础组件命名保持语义稳定，业务页面再通过外层 class 调整间距和布局。

## 视觉节奏

同一屏内保持少量明确层级：

- app shell 和 pane 用结构色区分。
- panel 和 content area 用轻微 surface 差异或边框区分。
- 行项目用 hover、selected、active 和左侧细线/小色块表达状态。
- CTA 只在真正提交、创建、确认等动作上使用强强调。

## 文案节奏

默认不要用标题下的小字解释区域用途。视觉应先通过结构、空间、控件和状态建立理解。除非辅助文案会影响用户决策，否则移除它。

保留文案的判断标准：这句话是否能防止误操作、解释错误、说明权限/危险后果、或告诉空状态下一步。如果不能，就不要常驻显示。

## 中文界面要求

中文文案通常比英文更紧凑，但容易在窄控件中显得拥挤。按钮和菜单项优先使用短动词；说明文字控制在一到两行；中英文混排时保留合理空格，避免长英文 token 撑破布局。
