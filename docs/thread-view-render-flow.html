ThreadView 数据到渲染流程

这页按阅读顺序整理当前 thread view 的渲染流程。先看一句话总览，再沿着编号主链路往下读； 分支逻辑和 row 类型放在后面，避免打断主流程。

一句话： pane 先按 tab 内的 sessionViewMode 选择投影：Linear 从 ConversationStore 读取 active turns 并投影为 ThreadDisplayRow[]；Branch 从全历史 SessionMessageTree 计算轻量图布局，节点 inspect 通过上下文页签把配对的 user / assistant 内容投影到 Right Sidebar。

主链路 乐观发送 快速路径 关键分支 row 类型分发表 记忆边界

主链路

从数据进入 store 到 row 被组件渲染，按实际处理顺序阅读。

1

上游事件改变会话内容

source
输入

runtime stream event、history load、composer send。

处理

普通 Composer submit 先同步写入带 delivery=pending 的 user row；随后调用 updateConversationTurns 或 setConversations。runtime turn identity 到达时在同一 transaction 内把 pending:* 原子绑定/合并到 canonical turn，但不会提前确认 user message。

输出

下一版 ConversationTurnMap。

2

ConversationStore 维护源数据

canonical
输入

ThreadTurn[] 按 session 写入。

处理

deriveActiveMessages(turns) 扁平化 turn 内 messages。

输出

conversations[sessionID]，即 ThreadMessage[]。

3

WorkbenchPaneSurface 选择 session 投影并组装输入

pane
输入

useConversationTurns(conversationStore, pane.sessionID)。

处理

sessionViewMode 按 workbench tab 保留；从同一 turns snapshot 派生 messages，并同时接收全历史 messageTree。

输出

Linear 输出完整 ThreadViewProps；Branch 输出 SessionMessageTree、camera/inspect snapshot 和 onInspectMessage 回调。

4

Linear ThreadView 决定是否渲染真实内容

visibility
输入

isThreadVisible。

处理

Linear 中非 active panel 走 InactiveThreadView，可见时进入 VisibleThreadView。Branch 不进入 linear row projection，而是调用 buildBranchThreadLayout()。

输出

Linear 进入完整 row 渲染；Branch 只渲染全图摘要节点。节点点击打开或更新 Right Sidebar 的唯一 message-inspector 页签，并把同一 message ID 写入当前 tab 的 composerParentMessageID；点击本身不改变 active branch，下一次发送才以该节点为 parent 创建分支。

5

useThreadProjection 把消息投影成 rows

projection
输入

activeMessages、trace visibility、pending permission、messageTree。

处理

排序 assistant block，构建 display context，生成 base rows，再追加 decoration rows。

输出

displayRows: ThreadDisplayRow[]。

6

ThreadRows 渲染统一虚拟 row 窗口

list
输入

displayRows 和滚动容器状态。

处理

Active session 始终只渲染 TanStack virtual range、overscan rows 与临时 pinned rows；折叠的 process rows 不进入 displayRows。

输出

一组需要调用 renderRow(row) 的可见 row。

7

ThreadRowRenderer 按 row.kind 分发

render
输入

单个 ThreadDisplayRow。

处理

assistant-execution-summary 由 VisibleThreadView 渲染真实 button；其余 row 根据 row.kind 选择 user、permission、trace、diff 或 actions 外壳。

输出

屏幕上的 thread row；trace item 最终继续交给 TraceItemView。

用户消息乐观发送生命周期

user row 先出现，后端事件只更新同一 row；message ID 和 virtual row ID 始终稳定。

1. optimistic

普通新回合在 bridge 调用前写入 pending:${messageID}，并在 registry 保存完整 transport request snapshot。新会话在 create tab 切换成 ThreadView 后也先写入 user row，再等待模型与 workflow 的 pre-send 初始化，避免空白 ThreadView。Queue / Steer 不进入这条路径。

2. turn bound

turn.started 或 execution.mode 只把 pending turn 绑定到 canonical turnID；Loader 继续显示。

3. recorded

只有当前 attempt 的 message.recorded(role=user) 清除 delivery 并删除完整请求快照。history reconciliation 保留本地 user message ID。

4. failed / retry

确认前 error 或 cancel 保留 user row、移除空 assistant placeholder。Retry 复用原 row 与原始请求，生成新 clientTurnID，并清除旧 attempt identity 以隔离迟到事件。

Branch Chat overlay

activeTurns = history + live assistant overlay + optimistic user turns。确认后只在 tab 生命周期内保留轻量 message/turn alias；关闭 tab 后丢弃本地状态。

滚动与持久化

首次 append 遵守 follow / detached 规则；pending、failed、confirmed 不创建新 row。带 delivery 的 user message 不写 presentation storage，重载以后端 history 为准。

快速路径

只想记住主线时，看这一行即可。

Composer optimistic user / Runtime / History → ConversationTurnMap → deriveActiveMessages() → WorkbenchPaneSurface → useThreadProjection() → deriveThreadExecutionGroups() → ThreadPresentationStore → ThreadRows → ThreadRowRenderer

关键分支

这些分支会影响读到的 UI，但不改变主数据路径。

可见性分支

isThreadVisible === false 时只渲染 InactiveThreadView，避免非 active pane 继续渲染大量 rows。

投影两阶段

base rows 展开 message 和 trace；decoration rows 只追加最终 assistant 消息后的 diff 和 actions。

虚拟列表

Active session 始终启用，先用 estimated height 布局，再通过 ResizeObserver 更新实测高度；焦点 row 与 projection transaction anchor 会临时 pin。

Turn execution disclosure

Canonical ThreadTurn 先派生 ThreadExecutionGroup；同 backend execution 在任一帧最多一个 summary。投影只对有 backend/segment 强身份的重复 canonical wrappers 做保守归并，随后由 ThreadPresentationStore 决定是否从 displayRows 移除 process prefix。运行中的 text 仍可能是进度说明或中间输出，因此非 completed turn 始终完整显示 process rows，不生成 summary；只有 turn 以 completed 完成且 final response 已解析后才允许折叠。待回答和提交中的 assistant-question-row 属于 protected outcome；canonical metadata、结构化答案或历史答案快照确认已回答后，该 row 在最终回复之前归入 process prefix。completed turn 中 response 前的失败 trace 仍属于 process prefix；blocked、failed、cancelled、stopped、continued-by-user 或 completed 但无最终 response 时，所有 process 与终态 trace 均保持直接可见。自动折叠使用 semantic scroll-anchor transaction，不使用 CSS 隐藏 row。

row 类型分发表

ThreadRowRenderer 的核心工作就是这张表：输入 row.kind，输出对应 UI 外壳。

row.kind 渲染组件 / 外壳 用户看到什么
user-message UserThreadMessageArticle 用户输入内容，必要时附带 diff card。
permission-request PermissionRequestInlinePrompt 工具权限确认、拒绝、自定义回答。
assistant-execution-summary AssistantExecutionSummary Turn 级处理状态、时长和 process prefix 展开/收起按钮。
assistant-response-row / assistant-file-change-row AssistantTraceSection → TraceItemView 主回复与文件变更摘要。
assistant-question-row AssistantTraceSection → QuestionTraceItemView 待回答时显示交互控件并作为 protected outcome 留在折叠区外；提交后隐藏状态行，以本地化的“问题：”“回答：”短前缀形成只读摘要。服务端或历史答案确认后，最终回复之前的已回答卡片归入 process prefix。
assistant-reasoning-row / assistant-tool-row / assistant-workflow-row / assistant-source-row / assistant-approval-row / assistant-debug-row AssistantTraceLite → TraceItemView reasoning、工具、workflow、source、approval、debug 轨迹。
assistant-ephemeral-state AssistantMessagePlaceholder Preparing、Thinking、Running tools 等临时状态。
assistant-inserted-user-message UserThreadMessageArticle stream insertion 中插回 assistant 流程的 user message。
assistant-diff-card MessageDiffCard 文件变更 review / restore / open file。
assistant-actions branch / copy / fork action buttons 回复下方的操作栏。

记忆点 1：源数据

ConversationTurnMap 是源数据；activeMessages 只是给 UI 使用的扁平派生视图。

记忆点 2：投影单位

ThreadView 真正渲染的不是 message，而是 ThreadDisplayRow。

记忆点 3：渲染分发

ThreadRowRenderer 只看 row.kind，不重新推导完整会话结构。
