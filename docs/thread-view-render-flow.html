ThreadView 数据到渲染流程

这页按阅读顺序整理当前 thread view 的渲染流程。先看一句话总览，再沿着编号主链路往下读； 分支逻辑和 row 类型放在后面，避免打断主流程。

一句话： 运行事件写入 ConversationStore，pane 订阅当前 session 的 activeMessages， ThreadView 投影成 ThreadDisplayRow[]，最后按 row.kind 渲染成屏幕 UI。

主链路 快速路径 关键分支 row 类型分发表 记忆边界

主链路

从数据进入 store 到 row 被组件渲染，按实际处理顺序阅读。

1

上游事件改变会话内容

source
输入

runtime stream event、history load、composer send。

处理

调用 updateConversationTurns 或 setConversations。

输出

下一版 ConversationTurnMap。

2

ConversationStore 维护源数据

canonical
输入

ThreadTurn[] 按 session 写入。

处理

deriveActiveMessages(turns) 扁平化 turn 内 messages。

输出

conversations[sessionID]，即 ThreadMessage[]。

3

WorkbenchPaneSurface 组装 ThreadView 输入

pane
输入

useConversationMessages(conversationStore, pane.sessionID)。

处理

合并 activeSession、messageTree、diff、permission、side chat、handlers。

输出

完整的 ThreadViewProps。

4

ThreadView 决定是否渲染真实内容

visibility
输入

isThreadVisible。

处理

非 active panel 走 InactiveThreadView；可见时进入 VisibleThreadView。

输出

可见 pane 才进入完整投影和 row 渲染。

5

useThreadProjection 把消息投影成 rows

projection
输入

activeMessages、trace visibility、pending permission、messageTree、side chat。

处理

排序 assistant block，构建 display context，生成 base rows，再追加 decoration rows。

输出

displayRows: ThreadDisplayRow[]。

6

ThreadRows 决定直接渲染还是虚拟化

list
输入

displayRows 和滚动容器状态。

处理

少量 rows 直接 map；达到 80 rows 后只渲染 virtualRange.items。

输出

一组需要调用 renderRow(row) 的可见 row。

7

ThreadRowRenderer 按 row.kind 分发

render
输入

单个 ThreadDisplayRow。

处理

根据 row.kind 选择 user、permission、trace、diff、actions 或 side chat 外壳。

输出

屏幕上的 thread row；trace item 最终继续交给 TraceItemView。

快速路径

只想记住主线时，看这一行即可。

Runtime / History / User input → ConversationTurnMap → deriveActiveMessages() → WorkbenchPaneSurface → useThreadProjection() → ThreadRows → ThreadRowRenderer

关键分支

这些分支会影响读到的 UI，但不改变主数据路径。

可见性分支

isThreadVisible === false 时只渲染 InactiveThreadView，避免非 active pane 继续渲染大量 rows。

投影两阶段

base rows 展开 message 和 trace；decoration rows 只追加最终 assistant 消息后的 diff、actions、inline side chat。

虚拟列表

displayRows.length >= 80 时启用，先用 estimated height 布局，再通过 ResizeObserver 更新实测高度。

Inline side chat

assistant-inline-side-chat row 内部会渲染嵌套 ThreadView 和自己的 composer。

row 类型分发表

ThreadRowRenderer 的核心工作就是这张表：输入 row.kind，输出对应 UI 外壳。

row.kind 渲染组件 / 外壳 用户看到什么
user-message UserThreadMessageArticle 用户输入内容，必要时附带 diff card。
permission-request PermissionRequestInlinePrompt 工具权限确认、拒绝、自定义回答。
assistant-response-row / assistant-question-row / assistant-file-change-row AssistantTraceSection → TraceItemView 主回复、问题、文件变更摘要。
assistant-reasoning-row / assistant-tool-row / assistant-workflow-row / assistant-source-row / assistant-approval-row / assistant-debug-row AssistantTraceLite → TraceItemView reasoning、工具、workflow、source、approval、debug 轨迹。
assistant-ephemeral-state AssistantMessagePlaceholder Preparing、Thinking、Running tools 等临时状态。
assistant-inserted-user-message UserThreadMessageArticle stream insertion 中插回 assistant 流程的 user message。
assistant-diff-card MessageDiffCard 文件变更 review / restore / open file。
assistant-actions branch / copy / side chat / fork action buttons 回复下方的操作栏。
assistant-inline-side-chat InlineSideChatThread 某条 assistant 回复下方的分支讨论区。

记忆点 1：源数据

ConversationTurnMap 是源数据；activeMessages 只是给 UI 使用的扁平派生视图。

记忆点 2：投影单位

ThreadView 真正渲染的不是 message，而是 ThreadDisplayRow。

记忆点 3：渲染分发

ThreadRowRenderer 只看 row.kind，不重新推导完整会话结构。
